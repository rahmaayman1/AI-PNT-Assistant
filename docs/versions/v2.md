# v2 - Smoothed per-satellite C/N0 z-score detector

**Status:** designed, evaluated without leakage, frozen, and tested once on ds7.
Development notebook: `notebooks/Network_v2.ipynb`. Frozen artifacts: `models/v2/`.

v2 keeps the v1 baseline untouched and replaces the five v1 features by one informative quantity.
Every design decision below is backed by an experiment run under the same leakage-free protocol.

---

## 1. Why v2 exists

The re-evaluation of v1 ([v1.md](v1.md)) showed three problems:

1. The evaluation leaked (random row split of 5 Hz data) and choices were made on the test set.
2. Performance came almost entirely from one feature, the per-satellite C/N0 z-score.
3. The other four features added noise instead of information.

v2 fixes the evaluation first, and then simplifies the model using what the corrected evaluation shows.

---

## 2. What changed compared with v1

| Aspect | v1 | v2 |
|---|---|---|
| Evaluation | Random 70/30 row split of normal rows; attack rows all in the test set | Leave-one-scenario-out: the tested scenario is never in the fitting data |
| Threshold | 20th percentile of training scores, chosen by looking at test recall | 5% false-positive rate calibrated on the normal rows of a **different** scenario |
| Features | 5 (z-score, rolling std and diff of C/N0 and Doppler) | 3 (rolling means of the z-score over 5, 25, 50 samples) |
| Baseline | Pooled normal rows of cleanStatic, ds2, ds3 | Clean recording only (`cleanStatic`) |
| Std protection | None | Minimum baseline std of 0.5 dB |
| Metrics | Recall and precision at one operating point | AUC, recall at fixed FPR, and the calibrated operating point |
| Streaming | Rolling windows restart for every chunk | Per-satellite rolling state is kept across chunks |
| Final test | ds7 inspected while developing | ds7 evaluated once on the frozen models |

## 3. The detector

### Pipeline

```
channel observables (per satellite, 5 Hz)
  -> z = (cn0 - mean_sat) / max(std_sat, 0.5 dB)         baseline from cleanStatic normal rows
  -> causal rolling means of z over 5, 25, 50 samples     past samples only, per satellite
  -> StandardScaler -> Isolation Forest (200 trees, seed 42)
  -> flag if decision_function < threshold
```

Rows of satellites that are not in the baseline are dropped (as in v1). Handling unknown satellites explicitly
is a v3 topic.

### Features

| Feature | Meaning | Latency until the window is full |
|---|---|---|
| `z_roll_mean_5` | rolling mean of z, 5 samples | 1 s |
| `z_roll_mean_25` | rolling mean of z, 25 samples | 5 s |
| `z_roll_mean_50` | rolling mean of z, 50 samples | 10 s |

### Reference rule

`|rolling mean of z (25 samples)| > threshold` is kept next to the Isolation Forest. It needs no model file and
shows what the Isolation Forest adds (see section 6).

### Frozen configuration

| Item | Value |
|---|---|
| Baseline | per-satellite C/N0 mean/std from `cleanStatic` normal rows (floored at 0.5 dB) |
| Windows | 5, 25, 50 samples |
| Isolation Forest | 200 trees, `random_state=42`, scaler fitted on cleanStatic features |
| Calibration data | pooled normal rows of ds2 and ds3 |
| Target false-positive rate | 5% |
| Isolation Forest threshold | -0.1551 on the scikit-learn `decision_function` scale (flag if the value is below it) |
| Rule threshold | 1.792 on `|rolling mean of z (25)|` |

### Artifacts (in `models/v2/`)

| File | Content |
|---|---|
| `detector_v2.pkl` | fitted Isolation Forest |
| `scaler_v2.pkl` | fitted StandardScaler |
| `threshold_v2.txt` | Isolation Forest threshold |
| `baseline_v2_cn0_floored.csv` | per-satellite C/N0 mean and std (std floored at 0.5 dB) |
| `if_v2_config.json` | features, windows, floor, target FPR, calibration scenarios, threshold |
| `baseline_v2_cn0.csv`, `rule_v2_config.json` | baseline (not floored) and settings of the reference rule |

The saved files reproduce the in-memory predictions exactly (reload test: identical flags).
`GPSAnomalyDetector` in `model.py` loads the three Isolation Forest files without any change.

## 4. Evaluation protocol

1. Baseline and model are fitted on **normal rows only**.
2. The tested scenario is **never** part of the fitting data.
3. The alarm threshold comes from the normal rows of a **different** scenario.
4. Threshold-free metrics (AUC, recall at 1/5/10% false-positive rate) are reported together with the calibrated operating point.
5. ds2 and ds3 are **development** scenarios (they influenced design choices). ds7 is the final test, evaluated once.

---

## 5. Results

### Development scenarios (leave-one-scenario-out, threshold from the other scenario, target 5% FPR)

| Model | Test | AUC | Actual FPR | Recall |
|---|---|---|---|---|
| Isolation Forest, 3 windows (official) | ds2 | 0.986 | 5.3% | 0.988 |
| Isolation Forest, 3 windows (official) | ds3 | 0.916 | 4.4% | 0.690 |
| Isolation Forest, 25-sample window only | ds2 | 0.980 | 5.4% | 0.985 |
| Isolation Forest, 25-sample window only | ds3 | 0.903 | 4.3% | 0.665 |
| Simple rule, 25-sample window | ds2 | 0.995 | 5.3% | 0.986 |
| Simple rule, 25-sample window | ds3 | 0.904 | 4.6% | 0.711 |

For comparison, the v1 features under the same protocol: AUC 0.898 (ds2) and 0.840 (ds3), recall about 0.31 and 0.23 at 5% FPR.

### Final test on ds7 (frozen models, run once)

| Model | AUC | False-positive rate | Recall |
|---|---|---|---|
| Isolation Forest (official) | 0.669 | 3.3% | 14.4% |
| Simple rule | 0.671 | 3.7% | 18.5% |

Before the documented attack start the flag rate on ds7 stays near the normal level (0 to 8% per 20 s block), unlike the v1
detector, which started flagging earlier. At the documented start it jumps (about 37% in the first block) and afterwards stays irregular: roughly 10 to 33% in most blocks
of the attack, with a few blocks back at the normal level. ds7 is a power-matched attack, and C/N0 alone does not separate it.

## 6. Experiments and what they decided

| Experiment | Finding | Decision |
|---|---|---|
| Random vs temporal split of normal rows | Random split gives exactly the nominal FPR (0.050 and 0.199); temporal split gives 0.046 and 0.255 | Never use a random row split for 5 Hz data |
| Drift in clean data | Fitted on the first half of `cleanStatic`, the flag rate stays near 5% on the second half | Slow drift is not a general problem in a ~430 s clean recording |
| Scenario seen vs unseen | ds2 AUC 0.901 vs 0.898, ds3 0.846 vs 0.840 | The baseline transfers between scenarios of the same receiver; v1 was not memorizing scenarios |
| Ablation: remove the z-score | AUC falls to 0.63 (ds2), 0.59 (ds3), 0.53 (ds7) | The detector depends on the per-satellite C/N0 level |
| Feature sets | z-score alone: AUC 0.986 / 0.879 (ds2 / ds3) vs 0.898 / 0.840 for the 5 v1 features; adding the v1 features to the smoothed z-score lowers AUC (0.959 on ds2) | Drop the four extra features |
| Smoothing windows | AUC and recall change little (ds2 recall 0.985 to 0.989 for windows 1 to 50; ds3 0.675 to 0.751, partly because the actual FPR also rises from 4.5% to 5.5%) | Keep a 25-sample window as a compromise between noise and latency; add 5 and 50 for the Isolation Forest |
| Direction of the effect | Signed score gives AUC 0.186 on ds3 (reversed). In ds2, 11 of 14 satellites go up (+4 to +21 sigma) and 3 go down; in ds3 almost all go down | The effect is two-sided: use the absolute value in the rule |
| Noise per satellite | Normal C/N0 std is about 0.2 to 0.5 dB for most satellites, 2 to 3 dB for the weak satellite 11, about 0.04 to 0.05 dB for satellites 133 and 138 | Add a minimum std (floor) of 0.5 dB |
| Extreme satellites and floor | Excluding 133/138 barely changes ds2 and lowers ds3 recall at 5% FPR from 0.74 to 0.69; a 1.0 dB floor hurts ds3 at 1% FPR (0.65 to 0.21) | Results do not depend on two outlier satellites; the floor stays a safety net at 0.5 dB |
| Threshold calibration | Calibrated on another scenario at 5%, the actual FPR is 5.3% and 4.6%; at 1% it is unstable (2.0% and 0.4%) | Calibrate at 5%; statements about 1% need more normal data |
| Isolation Forest vs rule | Differences are small (ds3 recall 0.690 vs 0.711, AUC 0.916 vs 0.904) | Isolation Forest stays the official model; the rule is the reference. Feature quality, not model complexity, drives performance |

## 7. Limitations

- One receiver, one site, static scenarios, three attack recordings. ds2 and ds3 influenced the design, and ds7 has been used as a test twice
  (once per model), so it is no longer a clean test.
- ds7 (power-matched) is barely detected: recall 14 to 19% at 3 to 4% false positives.
- The per-satellite baseline is tied to the receiver and to the satellite geometry during the recording. Behaviour on GNSS-SDR data after the change
  is not shown yet.
- Neighbouring samples are strongly correlated and no confidence intervals are reported. Only about 10 minutes of normal data exist, so
  1% false-positive statements are unreliable.
- Detection is per satellite row. Detection delay and false alarm events per hour are not measured yet.
- Satellites that are not in the baseline are dropped silently.

## 8. What v3 tests next

Tracked in `notebooks/03_v3_improvements.ipynb`; nothing from it is part of v2.

1. Pseudorange and carrier phase (never used so far): consistency with Doppler, code-minus-carrier rate, common offset across satellites.
2. Epoch-level decision (k satellites for m consecutive epochs), detection delay, false alarm events per hour.
3. A calibrated confidence ("GPS quality") from the anomaly score, for the multi-source fusion stage.
4. Block-bootstrap error bars for recall and false-positive rate.
5. Self-calibration of the baseline on another receiver (GNSS-SDR), with the poisoning risk documented.
